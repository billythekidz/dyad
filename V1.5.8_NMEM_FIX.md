## 🐛 Bug Fixed

### Error:
```
Failed to save conversation to memory
```

### Root Cause:

From logs (`%APPDATA%\dyad\logs\main.log`):
```
stdout: 'Invalid memory type. Valid types: fact, decision, preference, todo, insight, context, instruction, error, workflow, reference'
```

**Problem:** Code was using `--type project --priority 9` but neural-memory doesn't support "project" as a memory type.

**Valid types:**
- fact
- decision
- preference
- todo
- insight
- context
- instruction
- error
- workflow
- reference

---

## ✅ Solution

**User feedback:** CLI usage shows `--type` is **optional** - nmem can **auto-detect** based on content.

### Changes Made:

**File:** `src/lib/auto_save_conversation.ts`

**Before:**
```typescript
// ❌ INVALID
const contextCommand = `remember "Project: ..." --type project --priority 9`;
const decisionCommand = `remember "..." --type decision --priority 8`;
const errorCommand = `remember "..." --type error --priority 7`;
```

**After:**
```typescript
// ✅ FIXED - Let nmem auto-detect
const contextCommand = `remember "Project: ..."`;
const decisionCommand = `remember "..."`;
const errorCommand = `remember "..."`;
```

**All `--type` and `--priority` flags removed** - nmem will auto-detect based on content.

## 🔧 Technical Details

### How nmem Auto-Detection Works:

nmem analyzes content to determine type:
- **Project summaries** → auto-detected as `context` or `fact`
- **Decision keywords** (decided, chose, selected) → auto-detected as `decision`
- **Error keywords** (error, bug, fix) → auto-detected as `error` or `workflow`
- **Features** (implemented, created) → auto-detected as `fact` or `insight`

### Priority Auto-Assignment:

nmem assigns priority based on:
- Recency (newer = higher)
- Connections (more related = higher)
- Frequency (accessed often = higher)
- Salience (important keywords = higher)

**No need to manually specify `--priority`!** 🎉
